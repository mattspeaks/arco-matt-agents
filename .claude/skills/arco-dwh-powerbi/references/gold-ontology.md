## Build and push (skill scripts)

Run both from the D&A project root, or set `ARCO_ONTOLOGY_HOME` (output folder) and `ARCO_MODEL_DESCRIPTIONS` (reviewed description drafts, `<root>/<model>/definition/tables`).

1. **Build:** `python scripts/ontology/build_ontology.py [--refresh-inventory]`. It writes the full TMDL definition to `$ARCO_ONTOLOGY_HOME/definition`.
   - `--refresh-inventory` re-reads gold columns into `gold_inv.json`; run it after warehouse schema changes.
   - Entities and relationships are declared in the `ENTITIES` / `RELS` lists at the top. Descriptions merge from the model drafts via `DESC_MODEL`.
2. **Push:** `python scripts/ontology/push_ontology.py` (`--dry-run` first: syncs tags and lists any element that would get a NEW tag, no push). It syncs lineage tags from the live definition (updateDefinition matches by lineageTag; fresh tags fail with "No element with lineage tag ...", renames go through `RENAMES`) and then pushes.
   - Elements missing from the definition are deleted, including UI-made test entities.
   - Phase-1 property names stay stable; new entities prefix their properties on a name collision.
3. **Approval:** the ontology is shared, so push only with the user's go-ahead.

## Format rules (each one broke a real push or binding)

- **Item name:** letters, numbers and underscores only (no spaces).
- **No `synonym` on properties:** it causes a V4 parse "indentation" error. Put the original column name in the `///` description.
- **Property names:** no spaces, 26 characters or fewer, unique across ALL entities.
- **Entity key:** one string or int column, verified unique. Composite keys aren't allowed, so facts need single-column surrogate keys in gold first (see gold-pipeline.md).
- **Warehouse binding:** this exact pattern (copied from a UI-made binding):
  - expression `'DirectLake - gold' = AzureStorage.DataLake("https://onelake.dfs.fabric.microsoft.com/<wsId>/<warehouseId>", [HierarchicalNavigation=true])`;
  - partition annotations `ONT_WorkspaceId`, `ONT_ItemId`, `ONT_ItemKind = Warehouse`, `ONT_ItemName`, `ONT_WorkspaceName`, `ONT_PinnedAtUtc`.

  Without the annotations the source is read as a Lakehouse. With `Sql.Database` the "item kind couldn't be identified".
- **Backing-table column names must equal the gold column names,** quoted when they contain spaces (`column 'Project Number'`). Renamed columns make Instances fail with a generic "Oops". Properties keep clean names via `valueColumn: Dim_Project.'Project Number'`.
- **Double, not Decimal:** graph queries return null for Decimal.
- **DirectLake backing tables can't have calculated columns.** Join keys must exist in gold (e.g. Textura `Vendor ID + '-1'`). Relationships with mismatched column types are skipped by the builder, with a warning.
- **Graph view (Manage graph):** only supports lakehouse or mirrored delta tables, so warehouse-bound entities show Ineligible. The ontology agent and data agents work without it.
- **getDefinition** doesn't export UI-created entities, only their backing tables. To learn a new binding format, create a tiny test entity in the UI, read its backing table, then let the next push remove it.
